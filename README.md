## 服务端怎么选：六种软件，各有各的前置条件

**原版（server.jar）** 是官方服务端，不带插件和模组接口，配置要求最低，适合先验证「服务器能不能跑起来」这件事。它加不了模组，想装模组得换加载器。

**Paper** 是 Spigot 的高性能分支，兼容大部分 Bukkit 和 Spigot 插件，优化选项多，是国内生存服、插件服的主流选择。教程发布时对应的构建版本是 `paper-1.21-50`，现在去官方下载页拿最新构建即可，版本号会变。

**Fabric** 是轻量模组加载器，跟版本跟得快。它有个硬性前提：必须先放 **Fabric-API**，否则你后装的其他模组一个都不生效。Fabric 的 loader 版本要和服务端的 MC 版本对上，1.21 对应过 0.15.11，1.21.1 对应过 0.16.10，1.21.5 对应过 0.16.13，别拿一个 loader 通吃。

**Forge** 也是模组加载器，1.21 的搭建方式和别的服务端不一样，要先跑 installer 生成启动脚本，后面单独说。

**Mohist** 能让模组和插件同服运行，但它只更新到 **1.20.2**。想在 1.21 上同时跑模组和插件，目前没有现成的 Mohist 可用，只能二选一，或者退回 1.20.2。

**NeoForge** 是近两年分出来的加载器，部分 1.21 整合包已经转到它上面。跟着整合包走就行，包作者指定哪个加载器，服务端就用哪个，别拿 Forge 的 jar 去顶 NeoForge 的包。

## 服务器买多大：三种人三种答案

教程作者的原始表述是「服务器配置建议 4 核 8G 以上，最低不要低于 4 核 8G」，理由是「高版本的 java 服很吃单核性能和内存」。这个数字对应的是多人、带插件、长期在线的场景，不是所有人的起跑线。

两篇小服实操教程给出的参数低得多：一篇用 `java -Xms1G -Xmx4G` 跑 Fabric 1.21.1，另一篇用 `java -Xmx2G` 跑 Fabric。注意这两个是 JVM 堆内存，不是机器总内存，机器还要留出给系统和其他进程的部分。

按人数和玩法分：

- **单人测试、2 到 3 人原版生存**：2 核 4G，堆内存给 2 到 4G 够用。
- **5 到 10 人原版或 Paper、装几个插件**：4 核 8G，这是性价比最高的一档。
- **模组整合包**：内存优先，8G 起，具体看整合包作者写的推荐配置，大型包 16G 不夸张。
- **20 人以上、多插件、多世界**：核心和内存都要加，单核主频别掉。

CPU 比核心数更值得看。高版本 Java 服吃单核，14900K、13900K、5900X、7950X 这类高主频型号跑出来的 TPS 比同价位的多核低频机器稳。这也是为什么雨云游戏云按 CPU 型号分档，而不是只按核心数分。

系统镜像选 Debian 12，没有就 Debian 11。CentOS 7 装 MCSManager 时会提示操作系统版本过低，直接不给用，要上就上 Ubuntu 24.04 LTS 或 CentOS 8 以上。

## 版本对不上，是“朋友进不来”最常见的原因

Minecraft 1.21 在 2024 年 6 月 13 日发布，1.21 这条线一共走了十一次以上更新，最后一个版本 1.21.11 在 2025 年 12 月 9 日发布，之后 Mojang 改用了年份版本号。

这条线内部的版本并不都互通：

- **1.21 和 1.21.1 可以互通**，这是最省事的一对。
- 1.21.1 之后的大部分更新改了网络协议，1.21.4 的服务端不接收 1.21.11 的客户端，除非服务端装了 **ViaVersion**。
- 反过来，旧客户端要进新服务端，需要 **ViaBackwards**。
- 模组服没有这种宽容度，必须用整合包构建时指定的确切版本。

第三方服务器列表站的实时数据能说明 1.21 现在还有多少人在玩：某次抓取时，69 个登记的 1.21 服务器里有 34 个应答，合计 919 名玩家在线；过去 28 天最忙的时段在 15:00 UTC 前后。很多服主不往新版本迁，是因为要等服务端软件和每一个插件跟上，有时还得转换世界，索性留在能用的 1.21 版本，用 ViaVersion 放新客户端进来。

客户端这边也要手动对：启动器里新建一个安装，从版本列表里挑服务端报的那个版本，启动前在 Play 按钮旁边选中它。

## 开服最小步骤：从装 Java 到看见 Done

**第一步，装 Java 21。** 教程里的一键脚本是：

bash
wget https://gitee.com/zeruns/Linux-shell/raw/master/JDK21_Dragonwell21_install.sh && chmod +x JDK21_Dragonwell21_install.sh && bash JDK21_Dragonwell21_install.sh


手动装也行，解压后把 `bin/java` 软链到 `/usr/bin/java`，跑 `java -version`，看到类似 `openjdk version "21.0.3.0.3" 2024-04-16` 就对了。不同 MC 版本要求的 JDK 不一样，1.21 线要 21，装之前确认一下你下的服务端对应哪个版本。

**第二步，传 jar，写启动命令。** 以 Paper 为例：

bash
java -server -Xms128M -XX:MaxRAMPercentage=95.0 -Dfile.encoding=UTF-8 -Duser.country=CN -jar paper-1.21-50.jar


`-Xms128M` 是初始堆内存，`-XX:MaxRAMPercentage=95.0` 让 JVM 最多用系统可用内存的 95%，`-Dfile.encoding=UTF-8` 防中文乱码，`-Duser.country=CN` 把地区设成中国，部分插件会据此走国内镜像。

**第三步，同意 EULA。** 首次启动会提示 `You need to agree to the EULA in order to run the server`，打开 `eula.txt` 把 `false` 改成 `true`，保存，再启动一次。

**第四步，等 `Done`。** 控制台出现 `Done` 就是启动完成，可以进游戏了。

**第五步，改 `server.properties`。** 端口默认 25565，正版验证也在这个文件里关。同一台机器跑多个服务端，必须给每个实例分配不同端口，改完重启实例。

**第六步，放行端口。** 游戏端口 25565；用 MCSManager 面板的话还要 23333 和 24444 两个端口。TCP 和 UDP 都要在安全组或防火墙里放行，只开 TCP 会出现能连上但进不去的情况。

Forge 多两步。先跑 installer：

bash
java -Xms128M -XX:MaxRAMPercentage=95.0 -Dfile.encoding=UTF-8 -Duser.country=CN -jar forge-1.21-51.0.23-installer.jar -installServer


# -Xmx4G` 前面的 `#` 去掉，改成你实际能给的内存（比如 `-Xmx7G`，别超过机器总内存，留一点给系统），再把启动命令改成 `bash run.sh`。

## 开起来之后最容易踩的四个坑

**换存档后服务器起不来。** 把本地存档上传替换 `world` 文件夹，文件夹名必须还是 `world`。如果你用非 root 用户跑服务端，替换完要重新赋权，否则服务端写不进去：

bash
sudo chown -R mcfabricuser:mcfabricuser /minecraft


**装了模组没反应。** 先确认你用的不是原版 `server.jar`，原版加不了模组。再用 Fabric 的话，`mods` 里必须有 Fabric-API。连锁采集这类服务端模组，本地和服务端版本要完全一致；小地图这类客户端模组只放本地就行。

**直接打包 world 备份，备份可能是残缺的。** 服务器运行中归档，文件可能只写了一半。正确顺序是 `/save-off` 停自动存档，`/save-all` 保存全部，归档，再 `/save-on`。

**手动备份太麻烦，想自动化。** 用命名管道给运行中的服务端发指令：`mkfifo mc.fifo`，启动命令改成 `tail -f mc.fifo | java -Xmx2G -jar XXX.jar nogui > log.log`，然后写个脚本，每 5 分钟用 `list` 查一次在线人数，有人时每 20 分钟备份一次，默认保留 10 个备份，没人时自动停。这套东西不难写，但装之前先想清楚备份文件放哪、磁盘够不够。

## 下单前确认两件事

**面板和镜像。** 问清楚你要买的机型能不能一键装 MCSManager 面板，或者有没有预装好的 MC 镜像。MCSManager 是开源、支持分布式部署的控制面板，能集中管理多台机器、分配多用户权限，装好之后建实例、传文件、改配置都在网页上做，比纯 SSH 省事很多。如果机器不带面板，你得自己跑一遍安装脚本，多花二十分钟。
